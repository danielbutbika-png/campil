## 2. ארכיטקטורה
```
User context + Trip context ─┐
Trusted data (תחזית, OSM, מקורות רשמיים, קטלוג) ─┤→ Rules engine (חישובים, ספים) → Recommendation[] → Validation → UI (InsightCard)
Internal knowledge (Academy) ─┘                        ↑ (עתידי) Model: הסבר/ניסוח בלבד, על modelContext מצומצם
```
- **המודל לא מחליט מספרים ולא בטיחות.** כמויות, תאריכים, חשמל ומשקל — בקוד. תנאי שטח/סגירות — מקור רשמי בלבד.
- **פעולות:** כל פעולה (suggestEquipment, suggestMeals, suggestTasks…) תחזיר הצעה מובנית ← תצוגה מקדימה ← אישור משתמש ← כתיבה. היום הפעולות הקיימות הן קישור למסך הרלוונטי; פעולות כתיבה ייבנו עם מסך אישור.
- **הפרדה בממשק:** כל ראיה מסומנת עובדה / חישוב / הערכה / ניסוח AI / מידע חסר; ודאות גבוהה / בינונית / נמוכה; שעת חישוב; המנוע שכתב.

## 4. מה ייבנה עם מודל (אחרי החלטה)
Trip Assistant (שאלות על הטיול מתוך modelContext), Smart Guide (תשובה מתוך מדריכי Academy בלבד + "אין לי מידע"), ניסוח "למה" אנושי יותר. כל אחד: בדיקות Prompt Injection, כשל שירות → חזרה למנוע הכללים, מכסת שימוש למשתמש.
