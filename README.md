# CampIL — תכנון טיולים וקמפינג בישראל

PWA בעברית (RTL) לתכנון, אריזה, ביצוע ותיעוד של טיולים וקמפינג. עובדת במחשב, בטאבלט ובנייד (אייפון ואנדרואיד), ניתנת להתקנה למסך הבית ופועלת גם בלי קליטה.

## הרצה
```bash
npm install
npm run dev        # פיתוח
npm test           # בדיקות יחידה (מנועים, תפריט, משפחות, התראות, אלבום)
npm run test:rules # בדיקות כללי האבטחה מול Firestore Emulator (דורש Java)
npm run build      # בנייה ל-dist/ (נתיבים יחסיים — עובד מכל תת-תיקייה)
```
**ענפים ופרסום:** `source` — קוד המקור. כל דחיפה מריצה CI (`.github/workflows/ci.yml`): בדיקת טיפוסים (כולל קוד שלא בשימוש) ← בדיקות יחידה ← בנייה ← כללי אבטחה מול Firestore Emulator ← בדיקות דפדפן (`scripts/run-e2e.mjs`). **רק אם הכול עבר** — הבנייה נדחפת ל-`main` (האתר ש-GitHub Pages מגיש) ומתויגת `deploy-<זמן>-<sha>`. חזרה לגרסה קודמת: Actions ← CI ← Run workflow עם `ref` של תג קודם.
**סביבת בדיקות:** דחיפה לענף `staging` עוברת את אותן בדיקות ומפרסמת ל-`/campil/staging/` בלבד — פרויקט Firebase נפרד (`.env.staging`), אחסון מכשיר ומטמונים נפרדים (קידומת `campil-stg-`), ופס "סביבת בדיקות" בראש המסך. הייצור והבדיקות לא נוגעים זה בקבצים של זה. דוח תוצאות בענף `ci-reports`.
**בדיקות דפדפן מקומיות:** `npm run build && npx vite preview --port 4173` ואז `CHROME_PATH=... node scripts/run-e2e.mjs`. אלה בדיקות בדפדפן מדומה (Chromium headless בגודל טלפון) — לא בדיקה בטלפון אמיתי; לזה `docs/qa/REAL_DEVICE_TEST_SCRIPT.md`.
**מסמכים:** `docs/AUDIT.md` (ממצאי בדיקה), `docs/PLAN.md` (תוכנית עבודה), `docs/SECURITY.md` (הרשאות, מיגרציה, חזרה לאחור), `docs/qa/REAL_DEVICE_TEST_SCRIPT.md` (בדיקות ידניות).

| מחסן ציוד | מידות, משקל, "מושאל מ־", בדיקה תקופתית עם תזכורת, שיבוץ בטיולים קרובים, סכומים רק ממה שהוזן |
| חלוקת אחריות | בטיול של כמה משפחות: מי מכין כל ארוחה, מי קונה כל פריט, איזו משפחה אחראית על משימה, כמה כל משפחה מביאה מציוד משותף. לוח "מי אחראי על מה" עם התקדמות לכל משפחה, "חלוקה מהירה" של מה שלא נקבע, ותצוגת "מה שאנחנו קונים" |

| יומן ואלבומים | רשומות עם תמונות (נשמרות ב-IndexedDB), מיקום GPS או אתר. אלבום משותף לחברי הטיול; קולאז׳ וסרטון נוצרים ונשמרים **רק במכשיר** ויורדים אליו |

| מקורות | כל נתון מסומן: מאומת / רשמי / קהילה (OSM) / הערכה / חישוב אוטומטי / לא ידוע. אתרים: "לא אומת" עד שהמשתמש רושם בדיקה משלו (תאריך ומקור) |
| היסטוריה ולמידה | סיכום ודירוג טיול; הדירוגים והמועדפים משפיעים על ניקוד ההמלצות הבאות |

## החלטות מקצועיות (מתועדות)
1. **PWA סטטית + Firebase במקום Next.js + Supabase** — לפי בחירתך. השירותים הציבוריים (Open-Meteo, OpenFreeMap, Overpass) פתוחים וללא מפתח. עבודה מקומית מלאה בלי חשבון; שיתוף וסנכרון בזמן אמת דרך Firebase (Anonymous + Google Auth, Firestore) — ראו `docs/SECURITY.md`.
2. **Vite + React + TypeScript + Tailwind**, TanStack Query לנתוני שרת ומטמון, Zustand לשמירה מקומית, Zod לבדיקת טופס האשף (נטען רק עם האשף), MapLibre GL למפה (נטען רק כשצריך).
3. **ניתוב hash** — עובד ב-GitHub Pages ובאופליין ללא הגדרות שרת.
4. **תמונות** — אין תמונות צד שלישי (שאלת רישוי). נופי האזורים הם איורי SVG מקוריים שנוצרים בקוד.
5. **סימון שבילים** — סמן הקטגוריות (לבן-צבע-לבן) בהשראת שיטת סימון השבילים בישראל.
6. **קטלוג אתרים** — 55 אתרים מוכרים עם מיקום ואופי כללי. **בכוונה בלי** מחירים, שעות, מתקנים ודירוגים; כל כרטיס מסומן "לא אומת" ומפנה לאתר המפעיל. מתקני חניונים מ-OSM מוצגים רק לפי תגיות קיימות.
7. **ספי מזג אוויר** (קובץ `src/engine/weatherRules.ts`): גשם ≥40% או ≥1 מ״מ · לילה קר ≤12° (מאוד ≤5°) · חום ≥32° (כבד ≥36°) · משבים ≥40 קמ״ש (חזקים ≥60) · UV ≥8. אלה ספי תכנון של האפליקציה, לא התרעות רשמיות.
8. **כללי כמויות** — ביגוד: התבנית מהקובץ היא ללילה אחד; פריטים יומיים מקבלים +1 לכל לילה נוסף. כלי אוכל, כיסאות, כריות ושמיכות: אחד למשתתף (ומסומן חסר אם המאגר קטן מזה). **מים**: 3 ליטר לאדם ליום, 5 בדרום ובמדבר (קק״ל ורשות הטבע והגנים); אפשר לשנות בטיול או בהגדרות.
9. **השירות המטאורולוגי** — ה-API של IMS דורש הרשאה; לכן מוצגים קישורים להתרעות הרשמיות ולא נתונים מומצאים.
10. **מרחקים** — בקו אווירי, מסומן ככזה. ניווט בפועל דרך קישורי Waze / Google Maps.
11. **הרכב המשתתפים נקבע בכל טיול** — גיל ומגדר לכל משתתף. מהם נגזרים: מבוגרים/ילדים, ביגוד אישי לכל אחד (+1 סט החלפה מתחת לגיל 6), פריטי היגיינה לפי מגדר וגיל (גילוח 16+, היגיינה נשית 11+, דאודורנט 10+), חיתולים מתחת ל-3, מספר סועדים, התאמת מסלולים וההמלצות. כל שינוי בעריכת הטיול מחשב מחדש ציוד, תפריט ולו״ז. בני המשפחה בהגדרות משמשים רק לטעינה מהירה.
12. **נפח תא מטען** — אין API ציבורי לנתוני רכב. לכן: מאגר מאומת עם מקורות (נבדק 22.10.2026), ולשאר הדגמים חיפוש ברשת דרך Claude API עם מפתח של המשתמש, שנשמר רק במכשיר ולא נכלל בגיבוי. תוצאת חיפוש מוצגת עם קישור למקור ונשמרת רק באישור.
13. **תחנות דלק** — זיהוי החברה לפי תגיות OSM (brand / operator / name). תחנה בלי תגית מסומנת "אחר". מחירים ושעות לא מוצגים.
14. **שיתוף והרשאות** — קריאה רק לחברי הטיול; הצטרפות עם מפתח הזמנה שמתחלף בהסרה; ציוד פרטי של כל משפחה במסמך נפרד שרק היא קוראת. כל מכשיר מחשב מחדש רק את החלק שלו ברשימה (המארגן — משותף ומשפחתו; כל משפחה — שלה). פירוט ובדיקות: `docs/SECURITY.md`, `tests/rules/`.
15. **מדד מוכנות** = פריטים ארוזים ÷ פריטי אריזה פעילים, עם פירוט לפי קטגוריה. מוצג במפורש שאינו אישור בטיחות.

## מבנה
```
src/engine/     מנועים טהורים + בדיקות (weatherRules, packing, scoring, planner, build)
src/services/   Open-Meteo, Overpass/OSM
src/data/       אזורים, GeoJSON, אתרים, מתכונים, מדריכים, seed.json (מקובץ ה-Excel)
src/screens/    מסכים (כולם חוץ ממסך הבית נטענים לפי דרישה); src/screens/trip/ — לשוניות תוכנית הטיול
src/lib/cloud/  סנכרון Firestore, מודל, מיגרציה למסמכי משפחה
firestore.rules כללי האבטחה — מקור יחיד (גם המדריך באפליקציה קורא מהקובץ הזה)
tests/rules/    בדיקות כללים מול ה-Emulator
scripts/        build-regions.cjs, import-gear.py, e2e-*.mjs + run-e2e.mjs (בדיקות דפדפן), overflow-audit.mjs
```
עדכון הציוד מה-Excel: מחליפים את `seed/family-gear.xlsx` ומריצים `npm run seed` (משפיע על התקנה חדשה / אחרי איפוס).
