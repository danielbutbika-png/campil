# CampIL — תכנון טיולים וקמפינג בישראל

PWA בעברית (RTL) לתכנון, אריזה, ביצוע ותיעוד של טיולים וקמפינג. עובדת במחשב, בטאבלט ובנייד (אייפון ואנדרואיד), ניתנת להתקנה למסך הבית ופועלת גם בלי קליטה.

## הרצה
```bash
npm install
npm run dev        # פיתוח
npm test           # בדיקות למנועי ההמלצות, הציוד, הניקוד והתפריט
npm run build      # בנייה ל-dist/ (נתיבים יחסיים — עובד מכל תת-תיקייה)
```
**פריסה ל-GitHub Pages:** דוחפים ל-`main` ומפעילים Pages ← Source: GitHub Actions. ה-workflow ב-`.github/workflows/pages.yml` מריץ בדיקות, בונה ומפרסם.

| מטבח שטח | תפריט אוטומטי לפי ימים וסועדים, כשרות/צמחונות/טבעונות/אלרגיות, מתכונים, רשימת קניות מאוחדת עם "יש בבית" |

| היסטוריה ולמידה | סיכום ודירוג טיול; הדירוגים והמועדפים משפיעים על ניקוד ההמלצות הבאות |

## החלטות מקצועיות (מתועדות)
1. **PWA סטטית במקום Next.js + Supabase** — לפי בחירתך. אין שרת, ולכן אין מפתחות API בכלל: כל השירותים (Open-Meteo, OpenFreeMap, Overpass) פתוחים וללא מפתח. "אורח עם שמירה מקומית" מומש במלואו; סנכרון בין מכשירים — דרך קובץ גיבוי (כולל תמונות). מודל הנתונים (`src/lib/types.ts`) מוכן למעבר ל-Supabase.
2. **Vite + React + TypeScript + Tailwind**, TanStack Query לנתוני שרת ומטמון, Zustand לשמירה מקומית, Zod לבדיקת טופס האשף, MapLibre GL למפה.
3. **ניתוב hash** — עובד ב-GitHub Pages ובאופליין ללא הגדרות שרת.
4. **תמונות** — אין תמונות צד שלישי (שאלת רישוי). נופי האזורים הם איורי SVG מקוריים שנוצרים בקוד.
5. **סימון שבילים** — סמן הקטגוריות (לבן-צבע-לבן) בהשראת שיטת סימון השבילים בישראל.
6. **קטלוג אתרים** — 53 אתרים מוכרים עם מיקום ואופי כללי. **בכוונה בלי** מחירים, שעות, מתקנים ודירוגים; כל כרטיס מסומן "לא אומת" ומפנה לאתר המפעיל. מתקני חניונים מ-OSM מוצגים רק לפי תגיות קיימות.
7. **ספי מזג אוויר** (קובץ `src/engine/weatherRules.ts`): גשם ≥40% או ≥1 מ״מ · לילה קר ≤12° (מאוד ≤5°) · חום ≥32° (כבד ≥36°) · משבים ≥40 קמ״ש (חזקים ≥60) · UV ≥8. אלה ספי תכנון של האפליקציה, לא התרעות רשמיות.
8. **כללי כמויות** — ביגוד: התבנית מהקובץ היא ללילה אחד; פריטים יומיים מקבלים +1 לכל לילה נוסף. כלי אוכל, כיסאות, כריות ושמיכות: אחד למשתתף (ומסומן חסר אם המאגר קטן מזה). **מים**: אין כלל אוניברסלי — הכמות מחושבת רק אחרי שמגדירים ליטרים לאדם ליום בהגדרות.
9. **השירות המטאורולוגי** — ה-API של IMS דורש הרשאה; לכן מוצגים קישורים להתרעות הרשמיות ולא נתונים מומצאים.
10. **מרחקים** — בקו אווירי, מסומן ככזה. ניווט בפועל דרך קישורי Waze / Google Maps.
11. **הרכב המשתתפים נקבע בכל טיול** — גיל ומגדר לכל משתתף. מהם נגזרים: מבוגרים/ילדים, ביגוד אישי לכל אחד (+1 סט החלפה מתחת לגיל 6), פריטי היגיינה לפי מגדר וגיל (גילוח 16+, היגיינה נשית 11+, דאודורנט 10+), חיתולים מתחת ל-3, מספר סועדים, התאמת מסלולים וההמלצות. כל שינוי בעריכת הטיול מחשב מחדש ציוד, תפריט ולו״ז. בני המשפחה בהגדרות משמשים רק לטעינה מהירה.
12. **נפח תא מטען** — אין API ציבורי לנתוני רכב. לכן: מאגר מאומת עם מקורות (נבדק 22.10.2026), ולשאר הדגמים חיפוש ברשת דרך Claude API עם מפתח של המשתמש, שנשמר רק במכשיר ולא נכלל בגיבוי. תוצאת חיפוש מוצגת עם קישור למקור ונשמרת רק באישור.
13. **תחנות דלק** — זיהוי החברה לפי תגיות OSM (brand / operator / name). תחנה בלי תגית מסומנת "אחר". מחירים ושעות לא מוצגים.
14. **שיתוף** — מזהה הטיול בקישור הוא אקראי (20 תווים) ומשמש כמפתח: כללי Firestore מאפשרים קריאה/עדכון רק למי שמכיר את המזהה ומחובר, ללא אפשרות לרשום את כל הטיולים. רק המכשיר של יוצר הטיול מחשב מחדש את רשימת הציוד, כדי שמאגרי ציוד שונים של שותפים לא יתנגשו. בדיקות: `scripts/e2e-collab.mjs` מריץ שני דפדפנים נפרדים מול ממסר שמדמה את Firestore.
15. **מדד מוכנות** = פריטים ארוזים ÷ פריטי אריזה פעילים, עם פירוט לפי קטגוריה. מוצג במפורש שאינו אישור בטיחות.

## מבנה
```
src/engine/     מנועים טהורים + בדיקות (weatherRules, packing, scoring, planner, build)
src/services/   Open-Meteo, Overpass/OSM
src/data/       אזורים, GeoJSON, אתרים, מתכונים, מדריכים, seed.json (מקובץ ה-Excel)
src/screens/    מסכים; src/screens/trip/ — לשוניות תוכנית הטיול
scripts/        build-regions.cjs (פוליגונים), import-gear.py (Excel → seed), e2e.mjs (בדיקת עשן + צילומי מסך)
```
עדכון הציוד מה-Excel: מחליפים את `seed/family-gear.xlsx` ומריצים `npm run seed` (משפיע על התקנה חדשה / אחרי איפוס).
